# 决策记录：全栈作品集项目选型

> 用途：记录已定的结论与理由、待定问题。只追加，不覆盖历史。

## 已确定

### 2026-11-08 项目定位：求职作品集（B）
- 结论：按 B 类立项，但范围按「真能上线」的标准砍。
- 理由：首次全栈需要一个明确的完成信号；纯演示级的东西上线即散架，纯练技术又容易做成教程复刻。B 收敛范围，C 的标准保证质量。

### 2026-11-08 拷打强度：细问（3）
- 结论：按第 3 档推进，检查目标、约束、取舍和默认假设，随时可调。
- 理由：方向未成形时浅问问不出新信息；拷打档会把「选什么项目」这种还没成形的话题变成审问；细问刚好能逼出真实约束。

### 2026-11-08 启用决策记录
- 结论：决策写入本文件（`docs/decisions-project-selection.md`）。
- 理由：选型理由三个月后必忘，会重新纠结一遍；记录本身也是「会做技术决策」的作品集证据。

### 2026-11-08 约束确认（Q1～Q4）
- 时间预算：约 1 周。
- 开发方式：全程 AI 编程，本人不写代码，只负责熟悉项目。
- 目标岗位：前后端 / AI 应用；现有底子偏后端。
- 部署：项目完成后再考虑，现阶段不考虑。
- 需求来源：无具体场景（C），从岗位需求反推。
- 推论：范围按「本人能讲清楚」定，而不是按「功能多」定；一周的真实瓶颈是理解时间，不是生成时间。

### 2026-11-08 第三轮修正
- 方向要求：要有实际用途（自己与身边人会真的用），允许更复杂。
- 明确表示不必为「本人能否逐行讲清」压缩范围（该约束撤销，风险自担）。
- 每日投入 5～6 小时，一周合计约 35～40 小时。
- 部署：做；无部署经验，愿意付费购买服务器。

### 2026-11-08 方向确定：面试陪练（JD 驱动）
- 结论：选候选 1。
- 理由：本人即用户，投递期反馈闭环最短；AI 应用岗核心考点（结构化抽取 / 多轮 / 评分 / 成本）齐全；不依赖任何外部数据接口。
- 首批用户：无渠道，单人自测；因此不做任何增长、分享、邀请相关功能。
- 技术栈：前端 Vue 3，后端 ASP.NET Core Web API。
- 部署：项目完成后再做。

### 2026-11-08 MVP 边界（草案）
- 一条主流程：粘贴 JD → AI 抽取岗位 → 生成题目 → 作答 → 追问 → 四维评分 → 报告 → 弱点统计。
- 不做：爬取 JD、语音、多租户、社交分享、付费。

### 2026-11-08 范围变更（v2）
- 核心输入改为「个人简历 + 岗位 JD」；只做 JD 的 v1 作废，`docs/design-mvp.md` 仅留档。
- 部署移出范围，由用户自行解决。
- 流程改为：先写完 spec 并确认，再写代码。
- 已落地但将被 v2 覆盖：`db/schema.sql`（四表）、`backend/Qy.Api` 骨架（.NET 10 +
  EF Core 9 + Pomelo 9，`/health` 已连通 MySQL）。

### 2026-11-08 参数确认（最后一轮）
- 简历录入：粘贴文本 + PDF 上传（前端 pdfjs 抽文本，后端只收纯文本）。
- 报告：不做全篇简历改写，仅在 `gap` 题内给 `remediation`。
- 题量：8 题，`resume 3 + gap 3 + general 2`，`missing` 多时动态调整。
- 详细参数与验收标准见 `docs/spec-v2.md` §14。

### 2026-11-08 参考开源实现后的修订（R1～R5，全部采纳）
- R1 匹配分改加权公式（45/25/20/10，四项之和等于总分）——避免模型自由给分。
- R2 题目证据锚点，服务端校验引用合法——「为什么问这题」可验证。
- R3 追问动作由代码策略表决定，模型只生成措辞——避免跑偏。
- R4 弱点点固定 25 词表，白名单过滤——保证统计可聚合。
- R5 迷你离线评测集（10 case / 5 指标）——证明 prompt 不退化。
- 参考来源：OfferPilot（MIT）、agent-interview-coach（MIT）、resume-optimizer（MIT）。
- spec 定稿于 `docs/spec-v3.md`，`spec-v2.md` 仅留档。
